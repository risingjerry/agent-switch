# Rust core: one lightweight binary for secrets, MCP, CLIs and Skills

Status: approved direction (2026-10-26). Replaces the Python package and the
separate Skill Hub `skillctl` with one Rust binary named `agent-switch`.

## Goals

- One static binary, no runtime (no Python, no Node). Cold start < 5 ms for
  read-only commands; release binary < 5 MB; resident memory of `hub` < 10 MB.
- Drop-in compatible CLI for everything other tools already call (see
  "Compatibility contract"). Existing `~/.config/agent-switch/config.json` and
  `secrets.env` are read as-is; no migration step for users.
- Absorb Skill Hub: registry, lock, profiles, sync, plus new `usage` and
  `prune`.
- New `hub`: one stdio MCP server that starts backend MCPs only on first tool
  call, injects only their declared secrets, reaps them when idle, and tells
  clients when the tool set changes.

## Non-goals (this phase)

- cc-switch compatibility (`ccswitch/` module, `--no-ccswitch`, deeplinks):
  dropped. The flag is accepted and ignored so the macOS app keeps working.
- HTTP/SSE MCP normalization, OAuth. Remote MCPs stay as plain command entries
  (e.g. `npx mcp-remote`).
- Rewriting the macOS SwiftUI app. It keeps shelling out to the CLI and its
  JSON contracts stay stable.

## Crate layout

Single crate, single binary. Modules mirror today's Python packages:

```
src/main.rs          argument parsing and dispatch
src/config.rs        config.json model (serde), paths, atomic writes + backups
src/secrets.rs       secrets.env parse/write, flock, fd I/O, inventory
src/mcp.rs           registry CRUD, import from native configs
src/render/          claude.rs, claude_desktop.rs, codex.rs, hermes.rs
src/reconcile.rs     preview / apply / doctor / status (drift)
src/run.rs           `run <tool-id>`: exec a backend with only its secrets
src/hub.rs           lazy MCP proxy (stdio JSON-RPC)
src/skills/          registry.rs, lock.rs, profile.rs, sync.rs, usage.rs, prune.rs
src/clis.rs          CLI inventory
src/instructions.rs  managed runtime policy block
src/envelope.rs      --json output helpers
```

Dependencies, kept minimal: `serde`, `serde_json`, `toml_edit` (edit Codex
`config.toml` without destroying user formatting), `lexopt` (args; no clap),
`libc` (flock, fd ops, exec). No async runtime: `hub` uses one thread per
backend pipe. Release profile: `lto = "fat"`, `codegen-units = 1`,
`panic = "abort"`, `strip = true`, `opt-level = 3`.

## Compatibility contract (must not break)

1. `agent-switch secret set --stdin NAME`, `secret set --fd N NAME`,
   `secret get --fd N NAME` (value written only to fd N, never stdout/stderr;
   refuse if fd N is a TTY), `secret list`, `secret delete NAME`. Same name
   regex `^[A-Z][A-Z0-9_]*$`, same 64 KiB limit, same file format and quoting
   rules, same flock on the file, file mode 0600.
2. `doctor|status|reconcile|preview|agents|clis|skills|skills update`
   with `--json` keep the same JSON keys the macOS app reads
   (`macos-app/AgentSwitch/AgentSwitch/Models/AgentModels.swift`).
3. `mcp list|add|set|remove|enable|disable|import` with the same flags
   (`--name --command --arg= --secret= --env=K=V --app`).
4. Rendered native configs are byte-identical to the Python renderer output for
   the same input (golden tests), except that the per-tool wrapper becomes
   `agent-switch run <id>` instead of a generated Python script.
5. Only `agent-*` entries are ever touched in native configs.

## `run <tool-id>`

Replaces the generated Python wrappers in `~/.config/agent-switch/mcp/bin/`.
Reads `secrets.env`, strips inherited env vars whose names match
`KEY|TOKEN|SECRET|PASSWORD|PASSWD|CREDENTIAL|AUTH`, adds back only the tool's
declared secrets and `env` (expanding `${NAME}` references), then `execvp`s
the command. No child process left behind, no interpreter start-up.

## `hub` (lazy MCP proxy)

Registered in each client as a single MCP entry `agent-hub` →
`agent-switch hub`. Tools with `"mode": "hub"` (new optional field, default
`"direct"` so nothing changes until a tool opts in) are served through it.

- Startup: read config; for each hub tool, load the cached tool manifest
  `~/.cache/agent-switch/tools/<id>.json` (written the first time the backend
  runs, refreshed on each start). Answer `initialize` and `tools/list`
  immediately from cache, without starting any backend. Tool names are
  `<short-id>__<tool>`.
- First `tools/call` for a backend: spawn it via the same logic as `run`,
  perform MCP `initialize`, forward the call, keep it alive.
- Idle reaper: backend killed after `idleSeconds` (default 300) without calls.
- Hot reload: poll `config.json` mtime every 2 s; when the hub tool set
  changes, update the list and emit `notifications/tools/list_changed`
  (capability `tools.listChanged: true`). Clients that ignore the
  notification fall back to "new session picks it up".
- A backend with no cached manifest yet is started once in the background at
  hub start to build the cache, then reaped.
- Backend stderr goes to `~/.cache/agent-switch/logs/<id>.log`, never to the
  client.
- Failures return a JSON-RPC error for that call only; the hub stays up.

## Skills (absorbs Skill Hub)

Data stays where it is: sources under `~/AgentWorkspace/skill-hub/{vendor,own}`,
`config/registry.json`, `skills.lock.json`, `profiles/*.json`. The binary reads
the hub path from `config.json` key `skillHub` (default
`~/AgentWorkspace/skill-hub`).

Commands (parity with `skillctl`): `skills status`, `skills fetch SOURCE`,
`skills promote`, `skills enable PROFILE SKILL --source S --path P`,
`skills disable PROFILE SKILL`, `skills sync PROFILE [--prune]`,
`skills sync-global [--prune]` (= `global-sync-official`), `skills audit`.
`scripts/skillctl` in Skill Hub becomes a 3-line shim to these.

New:
- `skills usage [--days 60] [--json]`: count, per skill, the sessions that
  invoked it. Claude Code: `~/.claude/projects/**/*.jsonl`, `Skill` tool_use
  input `skill`, plus `tool_use` inputs that read a `<name>/SKILL.md`. Codex:
  `~/.codex/sessions/**/*.jsonl`, `function_call`/`custom_tool_call` payload
  arguments that reference `<name>/SKILL.md` (not the injected skills list).
  Incremental: cache per-file (size, mtime) → counts in
  `~/.cache/agent-switch/skill-usage.json`; a warm run only parses changed
  files. Also reports each enabled skill's listing cost (name + description
  characters).
- `skills prune [--days 60] [--profile global] [--apply]`: dry-run by default;
  lists enabled skills with zero uses in the window, excluding skills that are
  referenced by another enabled skill's SKILL.md (e.g. `wechat-md-publisher`
  → `design-system`) and an explicit `keep` list in the profile. `--apply`
  disables them in the profile and re-syncs. Never deletes source files.

## Phases

1. Core parity: config, secrets, mcp, render, reconcile/doctor/status, run,
   clis, skills list/update. Golden tests against the Python output. Ship
   behind the same binary name via Homebrew/pipx replacement.
2. Skills merge: skillctl parity + usage + prune; skillctl shim.
3. Hub: lazy proxy + hot reload; opt-in per tool with `"mode": "hub"`.
4. Remove the Python package after one week of parity on the maintainer
   machine.

## Verification

- `cargo test`: unit tests per module, golden render tests using the existing
  `tests/fixtures`, secret fd tests (TTY refusal, no stdout leakage).
- Parity script: run Python and Rust `preview --json` against a temp
  `--home/--user-home` copy and diff.
- Bench: `hyperfine 'agent-switch status --json'` vs Python.
- Hub: integration test with a tiny fake stdio MCP server fixture: list from
  cache without spawning, spawn on call, reap after idle, list_changed on
  config edit.
